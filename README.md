# Enterprise Service Management & Workflow Automation Portal

Project ID **WD-W5-005** · AB Infotech Solutions Pvt. Ltd. · Week 5 (Advanced, Full-Stack)

A web portal where employees submit IT / HR / Administration / Infrastructure requests, service agents process them, workflow rules keep statuses valid, and administrators monitor performance from a live dashboard.

## Tech stack

| Layer | Technology |
|---|---|
| Frontend | React 18 (Vite), React Router, plain CSS (responsive) |
| Backend | Node.js + Express (REST API) |
| Database | **MySQL 8** (`mysql2` driver, parameterised queries) |
| Auth | JWT (Bearer token) + bcrypt password hashing |
| Uploads | multer (files stored in `backend/uploads`) |
| Testing | Postman / curl + browser dev tools (see `docs/TEST_CASES.md`) |

## Features by module

1. **Authentication & roles** – register (creates Employee), login, logout, `Admin / Employee / Service Agent` roles, server-side authorization on every route, frontend route guards, input validation, 401/403 handling, login rate-limit (5 failures / 15 min).
2. **Service requests** – create with title, description, department, category, priority and attachments; unique ID (`REQ-2026-00007`); statuses *Open, Assigned, In Progress, Resolved, Closed*; request history per user; edit, delete, comment.
3. **Assignment & workflow** – auto-assignment to the agent with the lowest workload in the department; manual (re)assignment by admin; agents can take unassigned requests of their own department; SLA-based default deadlines (Critical 4h, High 24h, Medium 72h, Low 120h); invalid status transitions rejected; overdue requests flagged automatically (background job every minute); assignment + status history.
4. **Analytics & reporting** – totals / active / overdue / resolved, average resolution time, breakdowns by department, priority and status, date-range filter, searchable + sortable + paginated request table, **CSV export** (plain CSV generated by the API, with formula-injection protection).
5. **Notifications & audit trail** – notification on assignment / status change / comment / overdue, unread badge in the sidebar and header, per-request activity timeline recording who changed what and when, success / warning / error toasts.

## Workflow rules

```
Open ──► Assigned ──► In Progress ──► Resolved ──► Closed
              ▲             │              │
              └─────────────┘              └──► In Progress (reopen)
```

| Role | Can do |
|---|---|
| Employee | Create requests, see only own requests, edit/delete own while Open/Assigned, comment, close or reopen own *Resolved* request |
| Service Agent | See requests of own department + assigned to them, take unassigned requests, move own requests Assigned → In Progress → Resolved, change priority/deadline of own requests, comment, export CSV |
| Admin | Everything: all requests, assign/reassign, any valid status change, delete, user management, organisation-wide dashboard |

## Setup

**Requirements:** Node.js 18+ and MySQL 8 running locally.

### 1. Backend + database

```bash
cd backend
npm install
cp .env.example .env        # Windows: copy .env.example .env
# edit .env -> set DB_PASSWORD (your MySQL root password) and a long JWT_SECRET
npm run db:setup            # creates database `service_portal`, tables and sample data
npm start                   # API on http://localhost:5000
```

> `npm run db:setup` **drops and recreates** the portal tables. Alternatively import the files manually:
> `mysql -u root -p < database/schema.sql` then `mysql -u root -p < database/seed.sql`.

### 2. Frontend

```bash
cd frontend
npm install
npm run dev                 # http://localhost:5173
```

If the API runs somewhere else, copy `frontend/.env.example` to `frontend/.env` and set `VITE_API_URL`.

## Security notes

Passwords are hashed with bcrypt · all SQL is parameterised · authorization is enforced on the server for every endpoint (the UI only hides buttons) · uploads are limited by type and size · file downloads require login and request access · CSV export neutralises spreadsheet formulas.

## Suggested demo flow (5 minutes)

1. Log in as **employee@company.com**, submit a request with an attachment → it is auto-assigned.
2. Log in as the assigned **agent**, open it, move *Start work → Mark resolved*, add a comment.
3. Back as the **employee**: see the notification, close the request.
4. Log in as **admin**: dashboard KPIs and charts, date filter, overdue list, reassign a request, export CSV, manage users.
5. Show the activity timeline and try an invalid action (e.g. an employee opening another user's request → 403).
